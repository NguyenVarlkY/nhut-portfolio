# 시니어 엔지니어의 마인드셋: 차이를 만드는 사고와 태도

기술 역량은 책과 강의로 배울 수 있지만, **마인드셋**(사고방식)과 **태도**는 가장 배우기 어렵고, 주니어와 시니어 엔지니어 사이에 가장 큰 차이를 만드는 요소입니다.

## 1. 업무에서 중요한 마인드셋

### 1.1 서둘러 버그를 고치지 마라
**왜** 문제가 생겼는지 모른다면 고치지 마세요. 새로운 버그만 만들 뿐입니다. 단순하게 들리지만 매우 중요한 원칙입니다.

- 근본 원인을 이해하지 못한 채 버그를 고치는 것은 증상을 "숨기는" 것에 불과합니다.
- 항상 **진단**에서 **치료**로 가세요. 결코 그 반대가 아닙니다.

### 1.2 "왜"라는 사고 (5 Whys)
**5 Whys** 기법은 도요타 생산 방식에서 나왔습니다. 표면만 처리하는 대신 "왜"를 다섯 번 연속으로 물어 **근본 원인**(Root Cause)을 찾습니다.

**예시:**
- 버그: 새벽 2시에 시스템이 다운됨.
- 왜? → 서버의 RAM이 부족했다.
- 왜? → 서비스에 메모리 누수가 있었다.
- 왜? → 캐시가 비워지지 않았다.
- 왜? → TTL 메커니즘이 없었다.
- 왜? → 처음부터 아무도 그것을 설계하지 않았다.

=> 더 나은 해결책은 서버를 재시작하는 것이 아니라 TTL을 갖춘 **캐시를 재설계**하는 것입니다.

### 1.3 제품에 대한 책임감
시니어 엔지니어는 단지 "작업을 끝내는" 데서 그치지 않고 다음에도 관심을 둡니다:
- 코드가 프로덕션에서 안정적으로 동작하는가?
- 모니터링과 알림이 있는가?
- 문서와 테스트가 있는가?
- 다음 사람이 계속 유지보수할 수 있는가?

## 2. 전문가다운 태도

### 2.1 평생 학습 (Lifelong Learning)
기술은 매일 바뀝니다. 문법을 외우는 능력보다 **배우는 법을 배우는** 능력이 더 중요합니다.

- 매주 1~2시간을 새로운 기술 학습에 투자하세요.
- 사용하는 라이브러리의 소스 코드를 읽으세요.
- 블로그나 문서를 써서 지식을 다지세요.

### 2.2 소통과 팀워크
- 복잡한 기술 문제를 쉽게 설명하세요.
- 코드 리뷰는 판단이 아닌 건설적인 태도로 하세요.
- 어려운 일을 먼저 맡고 동료를 도우세요.

### 2.3 겸손과 열린 마음
- 틀렸을 때 기꺼이 인정하세요.
- 주니어를 포함해 모든 사람에게서 배우세요.
- 모르면 주저하지 말고 물어보세요.

> *"훌륭한 엔지니어는 실수를 하지 않는 사람이 아니라, 가장 빠르게 고치고 다시 반복되지 않게 하는 사람이다."*
