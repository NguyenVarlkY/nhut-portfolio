# GitLens 마스터하기: Git 작업 효율 극대화

GitLens는 Visual Studio Code에서 가장 인기 있는 확장 중 하나로, IDE에 내장된 Git 통합 기능을 크게 강화해 줍니다. VS Code를 코드 이력을 이해하고, 변경 사항을 추적하고, 팀과 효율적으로 협업하는 강력한 도구로 바꿔 줍니다.

## 왜 GitLens가 필요한가?

### 1. 코드 이력을 즉시 이해
- 각 코드 줄을 누가 변경했는지 확인(blame 주석)
- 각 변경의 맥락과 이유 이해
- 시간에 따른 파일의 변화 추적

### 2. 작업 효율 향상
- 에디터를 떠나지 않고 커밋 이력에 빠르게 접근
- 파일의 여러 버전 비교
- Git 이력을 시각적으로 검색하고 탐색

### 3. 팀 협업 개선
- 누가 코드베이스의 어느 부분을 작업하는지 명확히 파악
- 코드 리뷰 중 잠재적 문제 발견
- 익숙하지 않은 코드를 다룰 때 중요한 맥락 제공

## GitLens 설치 및 설정

### 1. 기본 설치
- VS Code 열기
- Extensions(Ctrl+Shift+X)로 이동
- "GitLens" 검색
- Install 클릭

### 2. 기본 설정
GitLens는 Settings(Ctrl+,) → "GitLens" 검색으로 설정할 수 있습니다

#### 추천 설정:
```json
{
  "gitlens.blame.toggleModeKey": "alt+ctrl+b",
  "gitlens.hovers.currentLine.over": "line",
  "gitlens.hovers.currentLine.enabled": true,
  "gitlens.advanced.blame": {
    "toggleModeKey": "alt+ctrl+b"
  },
  "gitlens.codeLens.authors.enabled": true,
  "gitlens.codeLens.recentChange.enabled": true,
  "gitlens.codeLens.recentChange.location": "after",
  "gitlens.keymap": "alternate"
}
```

## GitLens의 주요 기능

### 1. Blame 주석
- 각 코드 줄을 마지막으로 수정한 사람을 에디터에 바로 표시
- 마우스를 올리면 커밋 상세 정보 확인
- 클릭하면 이력에서 해당 커밋 열기

#### 사용 방법:
- blame 켜기/끄기: `Alt+Ctrl+B`
- blame 모드 변경: 하단 상태 표시줄에서
- 설정에서 표시 방식 사용자 지정

### 2. Code Lens
- 각 함수/클래스에 가장 최근 커밋 정보 표시
- 파일에 기여한 작성자 수 표시
- 커밋 보기, 새 브랜치 만들기 같은 빠른 작업 제공

#### Code Lens 종류:
- **Authors**: 파일에 기여한 작성자 목록 표시
- **Recent Change**: 이 코드를 마지막으로 변경한 커밋 표시
- **Revisions**: 함수/클래스가 수정된 횟수 표시

### 3. 커밋 이력과 검색
- 저장소의 커밋 이력에 빠르게 접근
- 키워드, 작성자, 날짜로 커밋 검색
- 브랜치, 태그 또는 기타 조건으로 커밋 필터링

#### 접근 방법:
- GitLens 뷰 열기: `Ctrl+Shift+P` → "GitLens: Focus on Repository View"
- 또는 왼쪽 사이드바의 GitLens 아이콘 클릭

### 4. 버전 비교
- 현재 파일을 이력의 어떤 버전과도 비교
- 서로 다른 두 브랜치 비교
- 특정 두 커밋 간의 차이 확인

#### 사용 방법:
- 탐색기에서 파일을 우클릭 → "GitLens: Open Changes"
- 또는 GitLens 뷰 → 커밋 선택 → "Compare with Working Tree"

### 5. 이력 탐색 (History Exploration)
- 커밋 메타데이터뿐 아니라 내용으로도 커밋 검색
- 특정 코드 줄이 언제 추가/삭제/수정되었는지 찾기
- 파일 간에 이동한 코드 추적

#### 사용 방법:
- GitLens 뷰에서 → 검색(돋보기) 아이콘 클릭
- 찾고 싶은 키워드 입력
- GitLens가 해당 키워드를 포함한 커밋을 보여 줌

### 6. 표시와 북마크
- 중요한 커밋을 표시해 빠르게 접근
- 코드의 중요한 위치에 북마크 생성
- 특정 브랜치의 변경 사항 추적

### 7. GitHub/GitLab/Bitbucket 통합
- VS Code에서 풀 리퀘스트를 바로 확인
- 에디터를 떠나지 않고 풀 리퀘스트 생성 및 리뷰
- PR의 댓글과 토론 확인

## 고급 기법

### 1. 실시간 협업
- 같은 파일을 실시간으로 편집 중인 사람 확인
- 다른 사람이 원격에 변경을 push하면 알림
- Live Share 같은 기능 지원

### 2. 사용자 지정 데코레이션
- blame 주석 표시 방식 사용자 지정(색상, 글꼴, 위치)
- 특정 유형의 커밋을 강조하는 사용자 지정 규칙 생성
- 변경된 줄 수, 영향받은 파일 등의 정보 표시

### 3. 고급 필터링과 검색
- 여러 조건을 동시에 사용해 커밋 검색(작성자 + 날짜 + 키워드)
- merge 커밋, 이슈 번호가 있는 커밋 등의 속성으로 필터링
- 검색에 정규 표현식 사용

### 4. 다른 도구와의 통합
- Prettier, ESLint 같은 다른 확장과도 잘 동작
- Jira, Trello 같은 작업 관리 도구와 통합
- GitFlow, GitHub Flow 같은 워크플로 지원

## GitLens 모범 사례

### 1. 비난이 아니라 이해를 위해 blame 사용하기
- blame의 목적은 잘못한 사람을 찾는 것이 아니라 맥락을 이해하는 것입니다
- 이상한 코드를 보면 "누가 이걸 썼지?"가 아니라 "왜 이렇게 작성됐을까?"라고 물어보세요

### 2. 코드 리뷰와 함께 활용하기
- 리뷰 전에 GitLens로 어떤 변경이 있었는지 파악하기
- 중요한 변경의 작성자 확인하기
- 리뷰 중 blame을 활용해 구체적인 질문하기

### 3. 디버깅에 활용하기
- 버그가 생기면 blame으로 문제 코드가 언제 추가되었는지 찾기
- 함수나 변수가 시간에 따라 어떻게 바뀌었는지 추적하기
- 버그를 유입시킨 커밋을 찾아 원인 파악하기

### 4. 성능 최적화
- 매우 큰 저장소에서는 불필요한 기능 끄기
- 원격 저장소 작업 시 캐싱으로 부하 줄이기
- 저장소 전체가 아니라 필요한 이력만 불러오도록 설정하기

### 5. 프로젝트별 설정
- 프로젝트별 설정은 워크스페이스의 `.vscode/settings.json`에 저장하기
- 일관된 경험을 위해 팀과 설정 공유하기
- 저장소의 크기와 복잡도에 맞게 설정 조정하기

## 실전 예시

### 예시 1: 중요한 함수의 이력 파악하기
```javascript
// calculateTotalPrice를 마지막으로 수정한 사람과
// 왜 그렇게 바꿨는지 확인하기
function calculateTotalPrice(items) {
  return items.reduce((total, item) => total + item.price * item.quantity, 0);
}
```
- blame으로 이 함수를 마지막으로 변경한 커밋 확인
- 커밋 메시지를 읽고 변경 이유 이해
- 관련된 이슈나 PR이 있는지 확인

### 예시 2: 죽은 코드(Dead Code) 찾기
- 이력 검색으로 함수가 마지막으로 호출된 시점 확인
- 오랫동안 호출되지 않은 함수라면 죽은 코드일 수 있음
- 앞으로 다시 사용할 계획이 있는지 확인

### 예시 3: 기능의 발전 과정 이해하기
- 특정 기능과 관련된 모든 커밋 추적
- 기능이 시간에 따라 어떻게 발전했는지 확인
- 어떤 설계 결정이 내려졌고 그 이유는 무엇인지 이해

## 자주 발생하는 문제 해결

### 1. GitLens에 정보가 표시되지 않을 때
- Git이 올바르게 설치·설정되어 있는지 확인
- Git 저장소 안에서 작업 중인지 확인
- 창 새로고침 시도(Ctrl+Shift+P → "Reload Window")

### 2. 큰 저장소에서 성능이 느릴 때
- 설정에서 불필요한 기능 끄기
- 전체 이력을 불러오는 대신 특정 커밋이나 파일 이력에 집중하기
- 모든 브랜치가 아니라 현재 브랜치의 이력만 불러오도록 설정

### 3. Blame 주석이 정확하지 않을 때
- 원격에서 최신 변경 사항을 pull했는지 확인
- 줄 끝 문자 문제(CRLF vs LF) 확인
- `git add --renormalize .`를 실행해 줄 끝 문자 정규화

### 4. 원격 저장소에 접근할 수 없을 때
- 인터넷 연결과 원격 저장소 접근 권한 확인
- 자격 증명이 올바르게 설정되어 있는지 확인
- `git fetch`를 직접 실행해 연결 확인

## GitLens vs 다른 Git 도구

### GitLens Free vs GitLens Pro
- **GitLens Free**: 일상적인 개발에 필요한 대부분의 기능 제공
- **GitLens Pro**(유료): 다음과 같은 기능 추가:
  - 고급 blame 시각화
  - 커밋 템플릿
  - 팀 통계
  - 병합 충돌 해결 도구
  - Rebase 시퀀서

### 다른 Git 확장과 비교
- **Git History**: 커밋 이력 보기에 집중, 인라인 기능은 적음
- **Git Graph**: 브랜치 그래프 보기에 탁월하지만 blame과 code lens가 없음
- **VS Code 내장 Git**: 기본적인 Git 작업은 제공하지만 GitLens의 고급 기능은 없음

## 결론

GitLens는 단순한 Git 확장이 아니라, 코드에 대한 이해와 작업 효율을 높여 주는 도구입니다. 올바르게 사용하면 GitLens는 다음과 같은 도움을 줍니다:

- **파악 시간 단축**: 코드의 배경을 찾느라 시간을 쓰는 대신 에디터에서 바로 확인
- **코드 리뷰 품질 향상**: 건설적인 피드백을 위한 중요한 맥락 제공
- **개인 역량 강화**: 더 효율적으로 일하고 팀 내에서 전문성을 보여 줌
- **학습 지원**: 소스 관리와 소프트웨어 개발의 모범 사례를 배우는 훌륭한 도구

blame 주석을 켜고 기본 기능부터 살펴보세요. GitLens에 익숙해지면 코드를 이해하고, 팀과 협업하고, 매일의 개발 업무에서 높은 품질을 유지하는 데 GitLens에 의지하게 될 것입니다.

목표는 GitLens의 모든 기능을 아는 것이 아니라, 여러분과 팀의 워크플로와 필요에 가장 잘 맞는 기능을 활용하는 법을 아는 것임을 기억하세요.
