# GitLens を使いこなす：Git での作業効率を最大化する

GitLens は Visual Studio Code で最も人気のある拡張機能の一つで、IDE に組み込まれた Git 連携を大きく強化してくれます。VS Code を、コードの履歴を理解し、変更を追跡し、チームと効率よく協力するための強力なツールに変えてくれます。

## なぜ GitLens が必要なのか？

### 1. コードの履歴をすぐに理解できる
- 各行を誰が変更したかを確認できる（blame 注釈）
- それぞれの変更の背景と理由を理解できる
- ファイルが時間とともにどう変わってきたかを追跡できる

### 2. 作業効率が上がる
- エディタを離れずにコミット履歴へすばやくアクセス
- ファイルの異なるバージョンを比較
- Git の履歴を視覚的に検索・ナビゲート

### 3. チームでの協力がスムーズになる
- 誰がコードベースのどの部分を担当しているかがはっきりわかる
- コードレビュー中に潜在的な問題を発見できる
- なじみのないコードを扱うときに重要な背景情報が得られる

## GitLens のインストールと設定

### 1. 基本的なインストール
- VS Code を開く
- Extensions（Ctrl+Shift+X）を開く
- 「GitLens」を検索
- Install をクリック

### 2. 基本的な設定
GitLens は Settings（Ctrl+,）→「GitLens」で検索して設定できます

#### おすすめの設定：
```json
{
  "gitlens.blame.toggleModeKey": "alt+ctrl+b",
  "gitlens.hovers.currentLine.over": "line",
  "gitlens.hovers.currentLine.enabled": true,
  "gitlens.advanced.blame": {
    "toggleModeKey": "alt+ctrl+b"
  },
  "gitlens.codeLens.authors.enabled": true,
  "gitlens.codeLens.recentChange.enabled": true,
  "gitlens.codeLens.recentChange.location": "after",
  "gitlens.keymap": "alternate"
}
```

## GitLens の主な機能

### 1. Blame 注釈
- 各行を最後に変更した人をエディタ上に直接表示
- ホバーするとコミットの詳細を確認できる
- クリックすると履歴内のそのコミットを開ける

#### 使い方：
- blame の切り替え：`Alt+Ctrl+B`
- blame モードの変更：画面下部のステータスバーから
- 表示方法は設定でカスタマイズ可能

### 2. Code Lens
- 各関数/クラスに最新のコミット情報を表示
- ファイルに貢献した作者の数を表示
- コミットの表示や新しいブランチの作成などのクイック操作を提供

#### Code Lens の種類：
- **Authors**：ファイルに貢献した作者の一覧を表示
- **Recent Change**：このコードを最後に変更したコミットを表示
- **Revisions**：関数/クラスが変更された回数を表示

### 3. コミット履歴と検索
- リポジトリのコミット履歴にすばやくアクセス
- キーワード、作者、日付でコミットを検索
- ブランチ、タグ、その他の条件でコミットを絞り込み

#### アクセス方法：
- GitLens ビューを開く：`Ctrl+Shift+P` →「GitLens: Focus on Repository View」
- または左サイドバーの GitLens アイコンをクリック

### 4. バージョンの比較
- 現在のファイルを履歴内の任意のバージョンと比較
- 2 つの異なるブランチを比較
- 特定の 2 つのコミット間の差分を確認

#### 使い方：
- エクスプローラーでファイルを右クリック →「GitLens: Open Changes」
- または GitLens ビュー → コミットを選択 →「Compare with Working Tree」

### 5. 履歴の探索（History Exploration）
- コミットのメタ情報だけでなく、内容でもコミットを検索
- 特定のコード行がいつ追加・削除・変更されたかを調べる
- ファイル間を移動したコードを追跡

#### 使い方：
- GitLens ビューから → 検索（虫眼鏡）アイコンをクリック
- 探したいキーワードを入力
- GitLens がそのキーワードを含むコミットを表示

### 6. マークとブックマーク
- 重要なコミットにマークを付けてすばやくアクセス
- コード内の重要な場所にブックマークを作成
- 特定のブランチの変更を追跡

### 7. GitHub/GitLab/Bitbucket との連携
- VS Code 内でプルリクエストを直接確認
- エディタを離れずにプルリクエストを作成・レビュー
- PR のコメントやディスカッションを確認

## 高度なテクニック

### 1. リアルタイムでの共同作業
- 同じファイルをリアルタイムで編集している人を確認
- 他の人がリモートに変更を push したときに通知
- Live Share などの機能をサポート

### 2. カスタマイズ可能な装飾
- blame 注釈の見た目（色、フォント、位置）をカスタマイズ
- 特定の種類のコミットを強調するカスタムルールを作成
- 変更行数や影響を受けたファイルなどの情報を表示

### 3. 高度な絞り込みと検索
- 複数の条件を同時に使ってコミットを検索（作者 + 日付 + キーワード）
- マージコミットや課題番号付きのコミットなどの属性で絞り込み
- 検索に正規表現を使用

### 4. 他のツールとの連携
- Prettier や ESLint などの他の拡張機能ともうまく動作
- Jira や Trello などのタスク管理ツールと連携
- GitFlow や GitHub Flow などのワークフローをサポート

## GitLens のベストプラクティス

### 1. 責めるためではなく、理解するために blame を使う
- blame の目的は、悪い人を探すことではなく背景を理解すること
- 奇妙なコードを見つけたら、「誰が書いたの？」ではなく「なぜこう書かれたのか？」と問う

### 2. コードレビューと組み合わせる
- レビューの前に GitLens で変更内容を把握する
- 重要な変更の作者を確認する
- レビュー中に blame を使って具体的な質問をする

### 3. デバッグに活用する
- バグに遭遇したら、blame で問題のコードがいつ追加されたかを調べる
- 関数や変数が時間とともにどう変わったかを追跡する
- バグを持ち込んだコミットを見つけて原因を理解する

### 4. パフォーマンスを最適化する
- 非常に大きなリポジトリでは、不要な機能をオフにする
- リモートリポジトリで作業するときはキャッシュで負荷を減らす
- リポジトリ全体ではなく、必要な履歴だけを読み込むよう設定する

### 5. プロジェクトごとの設定
- プロジェクト固有の設定はワークスペースの `.vscode/settings.json` に保存する
- 一貫した体験のために、設定をチームで共有する
- リポジトリの規模や複雑さに合わせて設定を調整する

## 実践例

### 例 1：重要な関数の履歴を調べる
```javascript
// calculateTotalPrice を最後に変更したのは誰か、
// そしてなぜそのように変えたのかを確認する
function calculateTotalPrice(items) {
  return items.reduce((total, item) => total + item.price * item.quantity, 0);
}
```
- blame でこの関数を最後に変更したコミットを確認する
- コミットメッセージを読んで変更の理由を理解する
- 関連する課題や PR があるかを確認する

### 例 2：デッドコードを見つける
- 履歴検索で、関数が最後に呼び出された時期を調べる
- 長い間呼び出されていない関数は、デッドコードの可能性がある
- 将来また使う予定があるかを確認する

### 例 3：機能の変遷を理解する
- 特定の機能に関連するすべてのコミットを追う
- その機能が時間とともにどう発展してきたかを確認する
- どのような設計判断が下され、なぜそうなったのかを理解する

## よくある問題のトラブルシューティング

### 1. GitLens に情報が表示されない
- Git が正しくインストール・設定されているか確認する
- Git リポジトリ内で作業しているか確認する
- ウィンドウを再読み込みしてみる（Ctrl+Shift+P →「Reload Window」）

### 2. 大きなリポジトリで動作が遅い
- 設定で不要な機能をオフにする
- 履歴全体を読み込む代わりに、特定のコミットやファイルの履歴に絞る
- すべてのブランチではなく、現在のブランチの履歴だけを読み込むよう設定する

### 3. Blame 注釈が正しくない
- リモートから最新の変更を pull しているか確認する
- 改行コードの問題（CRLF と LF）がないか確認する
- `git add --renormalize .` を実行して改行コードを正規化する

### 4. リモートリポジトリにアクセスできない
- インターネット接続とリモートへのアクセス権を確認する
- 認証情報が正しく設定されているか確認する
- `git fetch` を手動で実行して接続を確認する

## GitLens と他の Git ツールの比較

### GitLens Free と GitLens Pro
- **GitLens Free**：日々の開発に必要な機能のほとんどを提供
- **GitLens Pro**（有料）：次のような機能を追加：
  - 高度な blame の可視化
  - コミットテンプレート
  - チームの統計
  - マージコンフリクト解決ツール
  - Rebase シーケンサー

### 他の Git 拡張機能との比較
- **Git History**：コミット履歴の表示に特化しており、インライン機能は少ない
- **Git Graph**：ブランチのグラフ表示に優れているが、blame や code lens はない
- **VS Code 組み込みの Git**：基本的な Git 操作はできるが、GitLens の高度な機能はない

## まとめ

GitLens は単なる Git 拡張機能ではなく、コードへの理解と作業効率を高めるツールです。正しく使えば、GitLens は次のように役立ちます：

- **把握にかかる時間を短縮**：コードの背景を調べる手間をかけず、エディタ上ですぐに確認できる
- **コードレビューの質を向上**：建設的なフィードバックのための重要な背景情報を提供
- **個人の生産性を向上**：より効率的に働き、チーム内でプロ意識を示せる
- **学習を支援**：ソース管理とソフトウェア開発のベストプラクティスを学ぶ優れたツール

まずは blame 注釈をオンにして、基本的な機能から試してみましょう。GitLens に慣れてくると、コードの理解、チームとの協力、日々の開発業務での品質維持に、GitLens が欠かせない存在になっているはずです。

目標は GitLens のすべての機能を知ることではなく、あなたとチームのワークフローやニーズに最も合った機能を使いこなすことだと覚えておいてください。
