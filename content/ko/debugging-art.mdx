# 디버깅의 기술: 버그를 찾는 과학적 방법

코드는 누구나 쓸 수 있지만, 시니어 엔지니어는 **문제 해결(troubleshooting)** 능력에서 차이가 납니다. 전문적인 디버깅은 운이나 직감이 아니라, 과학적 방법 위에 세워진 **체계적인 프로세스**입니다.

## 1. 디버깅에서의 과학적 방법

### 1.1 관찰 (Observation)
가장 먼저이자 가장 중요한 단계: **버그를 재현할 수 있어야 합니다**(reproduce bug). 재현할 수 없다면 고칠 수도 없습니다.

- 버그로 이어지는 단계를 정확히 기록하세요.
- 입력, 출력, 시스템 상태를 기록하세요.
- 환경을 확인하세요: 어떤 브라우저, 어떤 버전, 어떤 기기인지.

### 1.2 가설 (Hypothesis)
버그가 **왜** 발생하는지 근거 있는 예측을 세우세요. 막연히 추측하지 말고 다음을 근거로 삼으세요:

- 코드베이스에 대한 지식.
- 에러 메시지.
- 로그와 스택 트레이스.
- 데이터 흐름에 대한 이해.

### 1.3 실험 (Experiment)
다음 방법으로 가설을 검증하세요:
- 의심되는 지점에 상세한 **로그**를 추가합니다.
- **디버거**로 브레이크포인트를 걸고 단계별로 관찰합니다.
- 코드를 **격리**(isolate)합니다: 잠시 주석 처리하거나, 변수를 분리하거나, 단순한 입력으로 시험합니다.
- 코드에서 **이진 탐색**을 합니다: 의심 범위를 계속 절반으로 줄입니다.

### 1.4 결론 (Conclusion)
근본 원인을 찾아 수정하고, 버그가 다시는 돌아오지 않도록 **테스트를 작성하세요**(**회귀 테스트**).

## 2. 고급 디버깅 기법

- **Rubber Duck Debugging:** "고무 오리"에게 코드를 설명해 보세요. 문제를 소리 내어 말하는 과정에서 답이 떠오르는 경우가 많습니다.
- **코드를 다시 읽으며 디버깅:** "이 코드는 무엇을 해야 하지?"가 아니라 "이 코드는 실제로 무엇을 하지?"라는 관점으로 한 줄씩 다시 읽으세요.
- **Git Bisect 활용:** 커밋 이력을 절반씩 나누어 버그를 일으킨 커밋을 찾습니다.
- **버전과 의존성 확인:** 많은 버그는 여러분의 코드가 아니라 라이브러리 버전 변경에서 비롯됩니다.

## 3. 필수 디버깅 도구

- **Browser DevTools:** Network 탭, Console, Sources, Performance.
- **Server-side:** 로그 파일, APM 도구(Datadog, Sentry), 모니터링.
- **Database:** 쿼리 로그, EXPLAIN, 인덱스 분석.
- **API:** Postman, curl, mock 서버.
