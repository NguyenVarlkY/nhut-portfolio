# 리팩터링 가이드: 코드 품질 개선하기

리팩터링은 기존 코드의 외부 동작을 바꾸지 않으면서 구조를 재구성하는 과정입니다. 목표는 소프트웨어 설계를 개선하고, 코드를 더 이해하기 쉽게 만들며, 유지보수 비용을 줄이는 것입니다.

## 왜 리팩터링이 필요한가?

### 1. 복잡도 감소
- 복잡한 코드는 이해하기 어렵고, 유지보수하기 어려우며, 버그가 생기기 쉽습니다
- 리팩터링은 로직을 단순화하고 코드를 더 명확하게 만듭니다

### 2. 가독성 향상
- 좋은 코드는 이야기처럼 읽혀야 합니다
- 리팩터링은 변수, 함수, 클래스에 의미 있는 이름을 붙이도록 도와줍니다

### 3. 새 기능을 위한 준비
- 깔끔한 코드는 확장하기 더 쉽습니다
- 새 기능을 추가하기 전에 리팩터링하면 버그 위험이 줄어듭니다

### 4. 유지보수 작업 감소
- 좋은 코드는 버그를 찾고 고치는 시간을 줄여 줍니다
- 리팩터링은 기술 부채(technical debt)를 줄이는 데 도움이 됩니다

## 리팩터링 원칙

### 1. 항상 테스트를 갖출 것
- 리팩터링 전에 충분히 좋은 테스트 스위트가 있는지 확인하세요
- 테스트는 리팩터링 후에도 동작이 바뀌지 않았음을 검증해 줍니다

### 2. 한 번에 조금씩 리팩터링할 것
- 작은 변경은 통제하기 쉽습니다
- 문제가 생기면 쉽게 되돌릴 수 있습니다

### 3. 꾸준히 할 것
- 리팩터링은 일회성 활동이 아닙니다
- 개발 과정 전반에 걸쳐 지속적으로 해야 합니다

## 기본 리팩터링 기법

### 1. Extract Method (메서드 추출)
```javascript
// 이전
function printOwing(invoice) {
  let outstanding = 0;
  console.log(`*************************`);
  console.log(`**** Customer Owes ****`);
  console.log(`*************************`);
  
  // 미지불 금액 계산
  for (const border of invoice.borders) {
    outstanding += border.amount;
  }
  
  // 마감일 기록
  const today = Date.now();
  invoice.dueDate = new Date(today + 30 * 24 * 60 * 60 * 1000);
  
  console.log(`Customer name: ${invoice.customer}`);
  console.log(`Amount owed: ${outstanding}`);
  console.log(`Due date: ${invoice.dueDate.toLocaleDateString()}`);
}

// 이후
function printOwing(invoice) {
  printBanner();
  const outstanding = calculateOutstanding(invoice);
  recordDueDate(invoice);
  printDetails(invoice, outstanding);
}

function printBanner() {
  console.log(`*************************`);
  console.log(`**** Customer Owes ****`);
  console.log(`*************************`);
}

function calculateOutstanding(invoice) {
  return invoice.borders.reduce((sum, border) => sum + border.amount, 0);
}

function recordDueDate(invoice) {
  const today = Date.now();
  invoice.dueDate = new Date(today + 30 * 24 * 60 * 60 * 1000);
}

function printDetails(invoice, outstanding) {
  console.log(`Customer name: ${invoice.customer}`);
  console.log(`Amount owed: ${outstanding}`);
  console.log(`Due date: ${invoice.dueDate.toLocaleDateString()}`);
}
```

### 2. Rename Variable (변수 이름 변경)
```javascript
// 이전
function getTotalPrice() {
  let t = 0;
  for (let i = 0; i < items.length; i++) {
    t += items[i].price * items[i].quantity;
  }
  return t;
}

// 이후
function getTotalPrice() {
  let totalPrice = 0;
  for (let i = 0; i < items.length; i++) {
    totalPrice += items[i].price * items[i].quantity;
  }
  return totalPrice;
}
```

### 3. Replace Temp with Query (임시 변수를 질의 함수로 바꾸기)
```javascript
// 이전
function getDistanceTraveled(time) {
  const result = 2 * Math.PI * radius;
  return result * time;
}

// 이후
function getDistanceTraveled(time) {
  return getBaseCircumference() * time;
}

function getBaseCircumference() {
  return 2 * Math.PI * radius;
}
```

## 효과적인 리팩터링 프로세스

### 1단계: 분석과 계획
- 리팩터링이 필요한 영역을 파악하기
- 구체적인 목표 정하기(가독성 향상, 복잡도 감소 등)
- 작은 단계들로 계획 세우기

### 2단계: 환경 준비
- 충분히 좋은 테스트 스위트 확보하기
- 모든 테스트를 실행해 안정적인 상태인지 확인하기

### 3단계: 작은 리팩터링 수행
- 한 번에 하나의 리팩터링 기법만 적용하기
- 변경할 때마다 테스트 실행하기

### 4단계: 테스트와 검증
- 전체 테스트 스위트 실행하기
- 동작이 바뀌었는지 확인하기

### 5단계: 반복
- 다음 영역으로 넘어가기
- 코드 품질 다시 평가하기

## 리팩터링 모범 사례

### 1. 한 번에 한 가지에 집중하기
- 한꺼번에 너무 많은 것을 하려 하지 마세요
- 각 커밋은 하나의 구체적인 리팩터링 목적만 가져야 합니다

### 2. 이유를 기록하기
- 커밋 메시지에 왜 리팩터링하는지 설명하세요
- 팀이 변경의 가치를 이해하는 데 도움이 됩니다

### 3. 도구 활용하기
- 대부분의 최신 IDE는 리팩터링을 지원합니다
- Rename, Extract Method 같은 기능을 적극 활용하세요

### 4. 필요 없을 때는 리팩터링하지 않기
- 코드가 잘 동작하고 문제를 일으키지 않는다면, 단지 "깔끔하게" 만들려고 리팩터링하지 마세요
- 리팩터링은 실질적인 가치를 가져와야 합니다

### 5. 계속 배우기
- Martin Fowler의 『Refactoring: Improving the Design of Existing Code』를 읽어 보세요
- 팀 내 지식 공유 세션에 참여하세요

## 리팩터링을 피해야 할 때

### 1. 마감 압박이 있을 때
- 긴급 버그 수정 중이라면 버그 수정을 먼저 하세요
- 리팩터링은 안정된 후에 해도 됩니다

### 2. 충분한 테스트가 없을 때
- 테스트 없이 리팩터링하는 것은 매우 위험합니다
- 먼저 충분한 테스트를 작성한 다음 리팩터링하세요

### 3. 곧 바뀔 코드일 때
- 가까운 미래에 이 코드가 완전히 바뀔 것을 안다면
- 리팩터링할 가치가 없을 수 있습니다

## 결론

리팩터링은 별개의 활동이 아니라 소프트웨어 개발과 떼려야 뗄 수 없는 일부입니다. 올바르게 수행하면 리팩터링은 다음을 가능하게 합니다:

- 코드 품질 향상
- 버그 위험 감소
- 장기적인 개발 속도 향상
- 팀 만족도 향상
- 유지보수 비용 절감

리팩터링은 기술이자 예술이라는 점을 기억하세요. 인내심, 세부 사항에 대한 주의, 소프트웨어 설계에 대한 깊은 이해가 필요합니다. 작고 매끄러운 변경부터 시작하고, 정확성을 지키기 위해 항상 테스트를 갖추세요.

리팩터링에 익숙해지면 코드의 "악취(code smell)"를 알아차리고 이를 정확히 어떻게 다뤄야 할지 알게 됩니다. 그것이 숙련된 개발자의 표시입니다. 단지 동작하는 코드가 아니라, 잘 동작하는 코드를 쓰는 것이죠.
