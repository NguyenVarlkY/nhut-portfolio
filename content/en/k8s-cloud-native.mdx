# Kubernetes & Cloud Native

Deploying applications on traditional servers is a thing of the past. In modern enterprise environments, **Kubernetes (K8s)** is the standard for container orchestration.

## Why I chose K8s
1. **Self-healing:** Automatically restarts containers when they fail.
2. **Auto-scaling:** Automatically scales the number of pods up or down based on traffic.
3. **Rollout/Rollback:** Ships new features without service interruptions.

## A cloud-agnostic mindset
Whether you pick AWS, Azure, or GCP, the core of Cloud Native is still **containers (Docker)** and **Infrastructure as Code (Terraform)**.
- Don't depend too heavily on a single provider's proprietary services (vendor lock-in) unless you need to.
- Design your application following the 12-Factor App principles so it can move easily between cloud providers.

## Advice for freshers
Don't rush to learn every cloud service. Start by:
1. Dockerizing your application.
2. Writing a Docker Compose file.
3. Learning basic K8s management (Deployment, Service, Ingress).
