# Kubernetes & Cloud Native

Anwendungen auf klassischen Servern zu deployen gehört der Vergangenheit an. In modernen Unternehmensumgebungen ist **Kubernetes (K8s)** der Standard für Container-Orchestrierung.

## Warum ich mich für K8s entschieden habe
1. **Self-healing:** Startet Container bei Fehlern automatisch neu.
2. **Auto-scaling:** Erhöht oder verringert die Anzahl der Pods automatisch je nach Traffic.
3. **Rollout/Rollback:** Neue Features ohne Serviceunterbrechung ausliefern.

## Cloud-agnostisch denken
Ob AWS, Azure oder GCP: Der Kern von Cloud Native bleibt **Container (Docker)** und **Infrastructure as Code (Terraform)**.
- Mach dich nicht unnötig von proprietären Diensten eines Anbieters abhängig (Vendor Lock-in).
- Entwirf deine Anwendung nach den Prinzipien der 12-Factor App, damit sie sich leicht zwischen Cloud-Anbietern umziehen lässt.

## Tipps für Berufseinsteiger
Lerne nicht alle Cloud-Dienste auf einmal. Fang so an:
1. Containerisiere deine Anwendung mit Docker.
2. Schreib eine Docker-Compose-Datei.
3. Lerne die Grundlagen der K8s-Verwaltung (Deployment, Service, Ingress).
