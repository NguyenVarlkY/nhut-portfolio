# 资深工程师的思维模式：造就差异的思维与态度

技术能力可以通过书本和课程学到，但 **思维模式（mindset）** 和 **态度** 是最难学的，也是初级与资深工程师之间最大的差别所在。

## 1. 工作中重要的思维模式

### 1.1 不要急着修 Bug
如果你不知道它 **为什么** 出错，就不要去修——你只会制造新的 Bug。这条原则听起来简单，却极其重要。

- 不理解根本原因就修 Bug，只是在“掩盖”症状。
- 永远从 **诊断** 走向 **治疗**，绝不能反过来。

### 1.2 “为什么”思维（5 Whys）
**5 Whys** 方法源自丰田生产方式：连续问 5 次“为什么”，找到 **根本原因（Root Cause）**，而不是只处理表面问题。

**示例：**
- 故障：系统在凌晨 2 点宕机。
- 为什么？→ 服务器内存耗尽。
- 为什么？→ 某个服务存在内存泄漏。
- 为什么？→ 缓存从未被清理。
- 为什么？→ 没有 TTL 机制。
- 为什么？→ 一开始就没人设计它。

=> 更好的解决方案是带上 TTL **重新设计缓存**，而不仅仅是重启服务器。

### 1.3 对产品负责
资深工程师不只是“完成任务”，还会关心：
- 代码在生产环境中运行稳定吗？
- 有监控和告警吗？
- 有文档和测试吗？
- 后来的人能继续维护吗？

## 2. 专业的态度

### 2.1 终身学习（Lifelong Learning）
技术每天都在变化。**学会如何学习** 的能力比背语法更重要。

- 每周花 1-2 小时学习新技术。
- 阅读你所用库的源代码。
- 写博客或文档来巩固知识。

### 2.2 沟通与团队精神
- 把复杂的技术问题讲得简单易懂。
- 以建设性而非评判的态度做代码评审。
- 主动承担难题，并帮助队友。

### 2.3 谦逊与开放
- 错了就勇于承认。
- 向所有人学习，包括初级工程师。
- 不懂就问，不要犹豫。

> *“优秀的工程师不是从不犯错的人，而是能最快修复错误、并确保它不再发生的人。”*
