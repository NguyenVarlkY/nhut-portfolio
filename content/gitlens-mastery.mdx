# Thành Thạo GitLens: Tối ƯU Hiệu Suất Làm Việc Với Git

GitLens là một trong những extension phổ biến nhất cho Visual Studio Code, giúp tăng cường khả năng tích hợp Git trực tiếp trong IDE. Nó biến VS Code thành một công cụ mạnh mẽ để hiểu lịch sử mã nguồn, theo dõi thay đổi và làm việc hiệu quả với team.

## Tại Sao Cần GitLens?

### 1. Hiểu Lịch Sử Mã Nguồn Trực Tức
- Xem ai là người thay đổi từng dòng mã (blame annotation)
- Hiểu bối cảnh và lý do đằng sau mỗi thay đổi
- Theo dõi sự phát triển của file qua thời gian

### 2. Tăng Hiệu Suất Làm Việc
- Truy cập nhanh vào lịch sử commit mà không rời khỏi editor
- So sánh các phiên bản khác nhau của file
- Tìm kiếm và điều hướng qua lịch sử Git một cách trực quan

### 3. Cải Thiện Hợp Tác Trong Team
- Hiểu rõ ai làm việc trên phần nào của codebase
- Phát hiện các vấn đề tiềm ẩn trong quá trình review code
- Cung cấp bối cảnh quan trọng khi làm việc với mã nguồn không quen thuộc

## Cài Đặt và Cấu Hình GitLens

### 1. Cài Đặt Cơ Bản
- Mở VS Code
- Vào Extensions (Ctrl+Shift+X)
- Tìm kiếm "GitLens"
- Nhấn Install

### 2. Cấu Hình Cơ Bản
GitLens có thể được cấu hình qua Settings (Ctrl+,) → Tìm kiếm "GitLens"

#### Cấu Hình Đề Xuất:
```json
{
  "gitlens.blame.toggleModeKey": "alt+ctrl+b",
  "gitlens.hovers.currentLine.over": "line",
  "gitlens.hovers.currentLine.enabled": true,
  "gitlens.advanced.blame": {
    "toggleModeKey": "alt+ctrl+b"
  },
  "gitlens.codeLens.authors.enabled": true,
  "gitlens.codeLens.recentChange.enabled": true,
  "gitlens.codeLens.recentChange.location": "after",
  "gitlens.keymap": "alternate"
}
```

## Các Tính Năng Chính Của GitLens

### 1. Blame Annotation (Chú Thích Trách Nhiệm)
- Hiển thị trực tiếp trong editor ai là người sửa đổi từng dòng mã
- Hover để xem thông tin chi tiết về commit
- Click để mở commit trong lịch sử

#### Cách Sử Dụng:
- Bật/tắt blame: `Alt+Ctrl+B`
- Thay đổi chế độ blame: qua thanh trạng thái ở dưới cùng
- Tùy chỉnh hiển thị qua settings

### 2. Code Lens (Gợi Ý Mã Nguồn)
- Hiển thị thông tin về commit gần nhất ở cuối mỗi hàm/lớp
- Hiển thị số lượng tác giả đã đóng góp vào file
- Cung cấp các hành động nhanh như xem commit, tạo nhánh mới

#### Các Loại Code Lens:
- **Authors**: Hiển thị danh sách tác giả đã đóng góp vào file
- **Recent Change**: Hiển thị commit gần nhất đã thay đổi dòng mã này
- **Revisions**: Hiển thị số lượng lần sửa đổi của hàm/lớp

### 3. Lịch Sử Commit và Tìm Kiếm
- Truy cập nhanh vào lịch sử commit của repository
- Tìm kiếm commit bằng từ khóa, tác giả, ngày tháng
- Lọc commit theo nhánh, tag, hoặc các tiêu chí khác

#### Cách Truy Cập:
- Mở GitLens view: `Ctrl+Shift+P` → "GitLens: Focus on Repository View"
- Hoặc nhấn biểu tượng GitLens ở thanh bên trái

### 4. So Sánh Các Phiên Bản
- So sánh file hiện tại với bất kỳ phiên bản nào trong lịch sử
- So sánh hai nhánh khác nhau
- Xem sự khác biệt giữa hai commit cụ thể

#### Cách Sử Dụng:
- Nhấp chuột phải vào file trong explorer → "GitLens: Open Changes"
- Hoặc từ GitLens view → chọn commit → "Compare with Working Tree"

### 5. Tìm Kiếm Lịch Sử (History Exploration)
- Tìm kiếm commit bằng nội dung, không chỉ bằng thông tin commit
- Tìm kiếm khi nào một dòng mã cụ thể được thêm/xóa/sửa
- Theo dõi sự di chuyển của mã nguồn giữa các file

#### Cách Sử Dụng:
- Từ GitLens view → nhấn biểu tượng tìm kiếm (kính lúp)
- Nhập từ khóa muốn tìm kiếm
- GitLens sẽ hiển thị các commit chứa từ khóa đó

### 6. Đánh Dấu và Bookmark
- Đánh dấu các commit quan trọng để truy cập nhanh
- Tạo bookmark cho các vị trí quan trọng trong mã nguồn
- Theo dõi các thay đổi trên các branch cụ thể

### 7. Tích Hợp Với GitHub/GitLab/Bitbucket
- Xem pull requests trực tiếp trong VS Code
- Tạo và review pull requests mà không rời khỏi editor
- Xem comments và discussions trên PR

## Các Kỹ Nâng Cao

### 1. Realtime Collaboration
- Xem ai đang chỉnh sửa cùng một file trong thời gian thực
- Thông báo khi có người khác push thay đổi lên remote
- Hỗ trợ cho các tính năng như Live Share

### 2. Customizable Decorations
- Tùy chỉnh cách hiển thị blame annotation (màu sắc, font, vị trí)
- Tạo các rule tùy chỉnh để highlight các loại commit cụ thể
- Hiển thị thông tin như số lượng dòng đã thay đổi, files affected, etc.

### 3. Advanced Filtering và Searching
- Tìm kiếm commit bằng nhiều tiêu chí cùng lúc (tác giả + ngày + từ khóa)
- Lọc commit theo các thuộc tính như merge commit, commit có issue number, etc.
- Sử dụng regular expressions trong tìm kiếm

### 4. Integration với Các Công Cụ Khác
- Hoạt động tốt với các extension khác như Prettier, ESLint
- Tích hợp với các công cụ quản lý task như Jira, Trello
- Hỗ trợ cho các workflow như GitFlow, GitHub Flow

## Best Practices Sử Dụng GitLens

### 1. Sử Dụng Blame Để Hiểu, Không Để Chỉ Trích
- Mục tiêu của blame là hiểu bối cảnh, không phải tìm người có lỗi
- Khi thấy một dòng mã lạ, hãy hỏi "Tại sao nó được viết như vậy?" thay vì "Ai viết điều này?"

### 2. Kết Hợp Với Code Review
- Trước khi review, sử dụng GitLens để hiểu những thay đổi đã làm
- Kiểm tra xem ai là tác giả của các thay đổi quan trọng
- Sử dụng blame để đặt câu hỏi cụ thể trong quá trình review

### 3. Tận Dụng Trong Quy Trình Phát Hiện Lỗi (Debugging)
- Khi gặp lỗi, sử dụng blame để tìm khi nào mã nguồn gây lỗi được thêm vào
- Theo dõi sự thay đổi của một hàm hoặc biến qua thời gian
- Tìm commit mà lỗi được giới thiệu để hiểu rõ nguyên nhân

### 4. Tối ƯU Hiệu Suất
- Tắt các tính năng không cần thiết nếu làm việc với repository rất lớn
- Sử dụng caching để giảm tải khi làm việc với remote repository
- Cấu hình để chỉ tải lịch sử cần thiết thay vì toàn bộ repository

### 5. Tùy Chọn Cho Dự Án Cụ Thể
- Tạo file `.gitlensrc` để lưu trữ cấu hình cho dự án cụ thể
- Chia sẻ cấu hình với team để đảm bảo trải nghiệm nhất quán
- Điều chỉnh cài đặt dựa trên kích thước và phức tạp của repository

## Ví Dụ Thực Tế

### Ví Dụ 1: Tìm Hiểu Lịch Sử Của Một Hàm Quan Trọng
```javascript
// Xem ai là người sửa đổi lần cuối hàm calculateTotalPrice
// và tại sao họ thay đổi nó như vậy
function calculateTotalPrice(items) {
  return items.reduce((total, item) => total + item.price * item.quantity, 0);
}
```
- Sử dụng blame để xem commit gần nhất đã thay đổi hàm này
- Đọc commit message để hiểu lý do thay đổi
- Kiểm tra xem có liên quan đến issue hoặc PR nào không

### Ví Dụ 2: Phát Hiện Mã Nguyên Tồn (Dead Code)
- Sử dụng tìm kiếm lịch sử để xem khi nào một hàm cuối cùng được gọi
- Nếu hàm không được gọi trong một khoảng thời gian dài, có thể là dead code
- Kiểm tra xem có kế hoạch sẽ sử dụng lại trong tương lai không

### Ví Dụ 3: Hiểu Sự Phát Triển Của Một Tính Năng
- Theo dõi tất cả các commit liên quan đến một tính năng cụ thể
- Xem cách tính năng này đã phát triển qua thời gian
- Hiểu các quyết định thiết kế đã được đưa ra và tại sao

## Khắc Phục Sự Cố Thường Gặp

### 1. GitLens Chưa Hiển Thông Tin
- Kiểm tra xem Git có được cài đặt và cấu hình đúng không
- Đảm bảo rằng bạn đang làm việc trong một Git repository
- Thử reload window (Ctrl+Shift+P → "Reload Window")

### 2. Hiệu Suất Chậm Trên Repository Lớn
- Tắt các tính năng không cần thiết trong settings
- Sử dụng tính năng "GitLens: Focus on Specific Commit" thay vì tải toàn bộ lịch sử
- Cấu hình để chỉ tải lịch sử của nhánh hiện tại thay vì tất cả nhánh

### 3. Blame Annotation Không Đúng
- Đảm bảo rằng bạn đã pull các thay đổi mới nhất từ remote
- Kiểm tra xem có vấn đề với line endings không (CRLF vs LF)
- Thử chạy `git add .renormalize` để chuẩn hóa line endings

### 4. Không Thể Truy Cập Remote Repository
- Kiểm tra kết nối internet và quyền truy cập vào remote
- Đảm bảo rằng credentials đã được cấu hình đúng
- Thử sử dụng `git fetch` thủ công để kiểm tra kết nối

## GitLens vs Các Công Cụ Git Khác

### So Sánh Với GitLens Free vs GitLens Plus
- **GitLens Free**: Cung cấp hầu hết các tính năng cần thiết cho phát triển hàng ngày
- **GitLens Plus** (phiên bản trả費): Thêm các tính năng như:
  - Advanced blame visualization
  - Commit templates
  - Team statistics
  - Merge conflict resolution tool
  - Rebase sequencer

### So Sánh Với Các Extension Git Khác
- **Git History**: Tập trung vào việc xem lịch sử commit, ít tính năng inline hơn
- **Git Graph**: Tuyệt vời để xem đồ thị nhánh, nhưng thiếu tính năng blame và code lens
- **VS Code Built-in Git**: Cung cấp các thao tác Git cơ bản, nhưng thiếu tính năng nâng cao của GitLens

## Kết Luận

GitLens không chỉ là một extension Git đơn thuần - nó là một công cụ tăng cường sự hiểu biết và hiệu suất làm việc với mã nguồn. Khi được sử dụng đúng cách, GitLens giúp:

- **Giảm Thời Gian Tìm Hiểu**: Thay vì phải mất thời gian để hiểu bối cảnh của một đoạn mã, bạn có thể xem ngay trong editor
- **Cải Thiện Chất Lượng Code Review**: Cung cấp bối cảnh quan trọng để đưa ra phản hồi xây dựng
- **Tăng Thể Hiện Cá Nhân**: Giúp bạn làm việc hiệu quả hơn và thể hiện sự chuyên nghiệp trong team
- **Hỗ Trợ Học Hỏi**: Là một công cụ học hỏi tuyệt vời để hiểu các thực천 tốt nhất trong quản lý mã nguồn và phát triển phần mềm

Hãy bắt đầu bằng cách bật blame annotation và khám phá các tính năng cơ bản. Khi bạn đã quen với GitLens, bạn sẽ bắt đầu thấy mình phụ thuộc vào nó để hiểu mã nguồn, làm việc với team và duy trì chất lượng cao trong công việc phát triển phần mềm hàng ngày.

Nhớ rằng mục tiêu không phải là biết tất cả các tính năng của GitLens, mà là biết cách sử dụng những tính năng phù hợp nhất với workflow và nhu cầu cụ thể của bạn và team của bạn.
