# Kubernetes とクラウドネイティブ

従来のサーバーにアプリケーションをデプロイする時代は終わりました。現代の企業環境では、**Kubernetes**（K8s）がコンテナオーケストレーションの標準です。

## なぜ K8s を選んだのか？
1. **Self-healing：** コンテナに障害が起きると自動で再起動します。
2. **Auto-scaling：** トラフィックに応じて pod の数を自動で増減します。
3. **Rollout/Rollback：** サービスを止めずに新機能をリリースできます。

## クラウドに依存しない考え方
AWS、Azure、GCP のどれを選んでも、クラウドネイティブの核心は **コンテナ（Docker）** と **Infrastructure as Code（Terraform）** です。
- 必要がない限り、特定ベンダー固有のサービスに依存しすぎないこと（vendor lock-in）。
- クラウドプロバイダー間を移行しやすいよう、12-Factor App の原則に沿ってアプリケーションを設計しましょう。

## 新人エンジニアへのアドバイス
すべてのクラウドサービスを一度に学ぼうと焦らないでください。まずは次のことから始めましょう：
1. アプリケーションを Docker 化する。
2. Docker Compose を書く。
3. K8s の基本的な管理を学ぶ（Deployment、Service、Ingress）。
