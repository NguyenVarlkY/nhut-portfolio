# シニアエンジニアのマインドセット：違いを生む考え方と姿勢

技術スキルは本や講座で学べますが、**マインドセット**（考え方）と **姿勢** は最も身につけにくく、ジュニアとシニアのエンジニアの間に最も大きな差を生むものです。

## 1. 仕事で大切なマインドセット

### 1.1 慌ててバグを直さない
**なぜ** 壊れているのかわからないなら、直してはいけません。新しいバグを生むだけです。単純に聞こえますが、非常に重要な原則です。

- 根本原因を理解せずにバグを直すのは、症状を「隠している」だけです。
- 常に **診断** から **治療** へ。決して逆にしてはいけません。

### 1.2 「なぜ」を問う思考（5 Whys）
**5 Whys** はトヨタ生産方式から生まれた手法です。表面的な対処ではなく、「なぜ」を 5 回続けて問うことで **根本原因（Root Cause）** を突き止めます。

**例：**
- 障害：深夜 2 時にシステムがダウンした。
- なぜ？ → サーバーのメモリが不足した。
- なぜ？ → サービスにメモリリークがあった。
- なぜ？ → キャッシュがクリアされていなかった。
- なぜ？ → TTL の仕組みがなかった。
- なぜ？ → 最初から誰も設計していなかった。

=> より良い解決策は、サーバーを再起動するだけでなく、TTL を備えた **キャッシュを再設計する** ことです。

### 1.3 プロダクトへの責任感
シニアエンジニアは「タスクを終わらせる」だけでなく、次のことにも気を配ります：
- コードは本番環境で安定して動くか？
- 監視とアラートはあるか？
- ドキュメントとテストはあるか？
- 次の人が保守を引き継げるか？

## 2. プロとしての姿勢

### 2.1 生涯学習（Lifelong Learning）
技術は日々変わります。構文を暗記する力よりも、**学び方を学ぶ** 力の方が重要です。

- 毎週 1〜2 時間を新しい技術の学習にあてる。
- 使っているライブラリのソースコードを読む。
- ブログやドキュメントを書いて知識を定着させる。

### 2.2 コミュニケーションとチームワーク
- 複雑な技術的問題をシンプルに説明する。
- コードレビューは批判ではなく、建設的な姿勢で行う。
- 難しい仕事を自ら引き受け、チームメイトを助ける。

### 2.3 謙虚さとオープンさ
- 間違っていたら素直に認める。
- ジュニアを含め、誰からでも学ぶ。
- わからないときは遠慮せずに質問する。

> *「優れたエンジニアとは、決してミスをしない人ではなく、最も速くミスを直し、二度と繰り返さないようにできる人だ。」*
