# Hướng Dẫn Refactoring: Cải Thiện Chất Lượng Mã Nguồn

Refactoring là quá trình tái cấu trúc mã nguồn hiện có mà không thay đổi hành vi bên ngoài của nó. Mục tiêu là cải thiện thiết kế phần mềm, làm cho mã nguồn dễ hiểu hơn và giảm chi phí bảo trì.

## Tại Sao Cần Refactoring?

### 1. Giảm Phức Tạp
- Mã nguồn phức tạp khó hiểu, khó bảo trì và dễ gây lỗi
- Refactoring giúp đơn giản hóa logic, làm cho mã nguồn rõ ràng hơn

### 2. Tăng Khả Năng Đọc Hiểu
- Mã nguồn tốt nên đọc được như một câu chuyện
- Refactoring giúp đặt tên biến, hàm, lớp có ý nghĩa

### 3. Chuẩn Bị Cho Tính Năng Mới
- Mã nguồn sạch sẽ dễ dàng mở rộng hơn
- Refactoring trước khi thêm tính năng mới giúp giảm nguy cơ lỗi

### 4. Giảm Công Việc Bảo Trì
- Mã nguồn tốt giảm thời gian tìm và sửa lỗi
- Refactoring giúp giảm nợ công nghệ (technical debt)

## Nguyên Tắc Refactoring

### 1. Luôn Có Test
- Trước khi refactoring, hãy đảm bảo có bộ test đủ tốt
- Test giúp xác minh rằng hành vi không thay đổi sau refactoring

### 2. Refactoring Nhỏ Mỗi Lần
- Thay đổi nhỏ, dễ kiểm soát hơn
- Dễ dàng quay lại nếu có vấn đề

### 3. Cam Kết Liên Tục
- Refactoring không phải là hoạt động một lần
- Nên làm liên tục trong suốt quá trình phát triển

## Kỹ Thuật Refactoring Cơ Bản

### 1. Extract Method (Trích Xuất Phương Thức)
```javascript
// Trước
function printOwing(invoice) {
  let outstanding = 0;
  console.log(`*************************`);
  console.log(`**** Customer Owes ****`);
  console.log(`*************************`);
  
  // tính toán outstanding
  for (const border of invoice.borders) {
    outstanding += border.amount;
  }
  
  // ghi nhận ngày đến hạn
  const today = Date.now();
  invoice.dueDate = new Date(today + 30 * 24 * 60 * 60 * 1000);
  
  console.log(`Tên khách hàng: ${invoice.customer}`);
  console.log(`Số tiền nợ: ${outstanding}`);
  console.log(`Ngày đến hạn: ${invoice.dueDate.toLocaleDateString()}`);
}

// Sau
function printOwing(invoice) {
  printBanner();
  const outstanding = calculateOutstanding(invoice);
  recordDueDate(invoice);
  printDetails(invoice, outstanding);
}

function printBanner() {
  console.log(`*************************`);
  console.log(`**** Customer Owes ****`);
  console.log(`*************************`);
}

function calculateOutstanding(invoice) {
  return invoice.borders.reduce((sum, border) => sum + border.amount, 0);
}

function recordDueDate(invoice) {
  const today = Date.now();
  invoice.dueDate = new Date(today + 30 * 24 * 60 * 60 * 1000);
}

function printDetails(invoice, outstanding) {
  console.log(`Tên khách hàng: ${invoice.customer}`);
  console.log(`Số tiền nợ: ${outstanding}`);
  console.log(`Ngày đến hạn: ${invoice.dueDate.toLocaleDateString()}`);
}
```

### 2. Rename Variable (Đổi Tên Biến)
```javascript
// Trước
function getTotalPrice() {
  let t = 0;
  for (let i = 0; i < items.length; i++) {
    t += items[i].price * items[i].quantity;
  }
  return t;
}

// Sau
function getTotalPrice() {
  let totalPrice = 0;
  for (let i = 0; i < items.length; i++) {
    totalPrice += items[i].price * items[i].quantity;
  }
  return totalPrice;
}
```

### 3. Replace Temp with Query (Thay Thế Biến Tạm Bằng Truy Vấn)
```javascript
// Trước
function getDistanceTraveled(time) {
  const result = 2 * Math.PI * radius;
  return result * time;
}

// Sau
function getDistanceTraveled(time) {
  return getBaseCircumference() * time;
}

function getBaseCircumference() {
  return 2 * Math.PI * radius;
}
```

## Quy Trình Refactoring Hiệu Quả

### Bước 1: Phân Tích và Lập Kế Hoạch
- Xác định khu vực cần refactoring
- Xác định mục tiêu cụ thể (cải thiện đọc được, giảm độ phức tạp, etc.)
- Lập kế hoạch các bước nhỏ

### Bước 2: Chuẩn Bị Môi Trường
- Đảm bảo có bộ test đủ tốt
- Chạy tất cả test để xác nhận trạng thái ổn định

### Bước 3: Thực Hiện Refactoring Nhỏ
- Áp dụng một kỹ thuật refactoring mỗi lần
- Chạy test sau mỗi thay đổi

### Bước 4: Kiểm Tra và Xác Minh
- Chạy toàn bộ bộ test
- Kiểm tra xem hành vi có thay đổi không

### Bước 5: Lặp Lại
- Tiếp tục với khu vực tiếp theo
- Đánh giá lại chất lượng mã nguồn

## Best Practices trong Refactoring

### 1. Tập Trung Vào Một Thing Mỗi Lần
- Đừng cố gắng làm quá nhiều thứ cùng một lúc
- Mỗi commit nên chỉ có một mục đích refactoring cụ thể

### 2. Ghi Lại Lý Do
- Trong commit message, giải thích tại sao bạn đang refactoring
- Điều này giúp team hiểu giá trị của thay đổi

### 3. Sử Dụng Công Cụ Hỗ Trợ
- Hầu hết IDE hiện đại đều có hỗ trợ refactoring
- Tận dụng các tính năng như Rename, Extract Method, etc.

### 4. Đừng Refactoring Khi Không Cần Thiết
- Nếu mã nguồn đang hoạt động tốt và không gây vấn đề, đừng refactoring chỉ vì "sạch sẽ"
- Refactoring nên mang lại giá trị thực tế

### 5. Liên Tục Học Tập
- Tham khảo sách "Refactoring: Improving the Design of Existing Code" của Martin Fowler
- Tham gia các buổi chia sẻ kiến thức trong team

## Khi Nào Nên Tránh Refactoring

### 1. Khi Hạn Chấp Chất Lượng
- Nếu đang trong giai đoạn khẩn cấp sửa lỗi, ưu tiên sửa lỗi trước
- Refactoring có thể được làm sau khi ổn định

### 2. Khi Không Có Test Đủ Tốt
- Refactoring mà không có test là rất nguy hiểm
- Đầu tiên hãy viết test đủ tốt trước khi refactoring

### 3. Khi Mã Nguồn Sẽ Bị Thay Đổi Sớm
- Nếu biết rằng mã nguồn này sẽ bị thay đổi hoàn toàn trong tương lai gần
- Có thể không值得 refactoring

## Kết Luận

Refactoring không phải là hoạt động riêng biệt mà là phần không thể tách khỏi quá trình phát triển phần mềm. Khi được thực hiện đúng cách, refactoring giúp:

- Tăng chất lượng mã nguồn
- Giảm nguy cơ lỗi
- Tăng tốc độ phát triển trong dài hạn
- Cải thiện sự hài lòng của team
- Giảm chi phí bảo trì

Nhớ rằng refactoring là một nghệ thuật cũng như là một kỹ năng. Nó đòi hỏi sự kiên nhẫn, sự chú ý đến chi tiết và hiểu sâu về thiết kế phần mềm. Bắt đầu từ những thay đổi nhỏ, liền mạch và luôn luôn có test để bảo vệ sự chính xác.

Khi bạn làm quen với refactoring, bạn sẽ bắt đầu thấy "mùi hôi" trong mã nguồn và biết chính xác cách xử lý chúng. Đây là dấu hiệu của một nhà phát triển thành thạo - không chỉ viết mã nguồn that works, mà viết mã nguồn that works well.
